# 環境高速化の教訓（kaggriculture より）

> 出典: kaggriculture リポジトリ `docs/plans/simulator/fast-sim.md`（2026-08）。
> 対象は `kaggle-environments` 上の農場シミュレータ `kaggriculture`。
> 当時の段階的な実装計画・CLI・Kaggle 提出に関する節は削除し、
> **環境を速くする前に何を測るべきか**という計測値と教訓だけを残している。

## 1. プロファイル: ゲームロジックは 1.7% しかなかった

1 エピソード（720 turn）を `cProfile` で計測した内訳。

| 内訳 | 時間 | 割合 |
|---|---|---|
| `structify`（dict を属性アクセス化） | 1.00s | 30.5% |
| その他 stdlib | 0.90s | 27.5% |
| `deepcopy` | 0.84s | 25.7% |
| `jsonschema` によるバリデーション | 0.39s | 11.9% |
| フレームワーク本体 | 0.08s | 2.6% |
| **ゲームロジック本体（`kaggriculture.py`）** | **0.06s** | **1.7%** |

遅いのはゲームではなくフレームワークだった。ゲームルールを自前で書き直しても
取り戻せるのは 1.7% で、引き換えにルールが公式とずれるリスクを負う。
そこで「**ルールは公式のまま、フレームワークだけ剥がす**」方針を取った。

**RL への読み替え**: Gymnasium のラッパー（型チェック、観測の正規化、
記録用ラッパー）が同じ役回りになりやすい。環境を JAX で書き直す前に、
まず 1 エピソードをプロファイルして、ルール本体の割合を確かめる。

## 2. フレームワークを剥がした結果

公式の `interpreter(state, env)` を自前ループから直接呼んだ。

| ワークロード | 公式 `env.run` | 直接呼び出し | 倍率 |
|---|---|---|---|
| 1 エピソード（720 turn） | 824 ms | 27 ms | 30x |
| 120 エピソード（プロセス並列込み） | 25.4 s | 1.9 s | 13x |

5 つの seed で最終所持金が公式と**ビット単位で一致**することを確認した。
並列込みの倍率が小さいのは、プロセス起動と環境生成が定数コストとして残るため。

## 3. 最大の罠: フレームワークが持っていた責務

公式フレームワークは毎ステップ `observation.step` を進めていたが、
interpreter 自身はそれを書かなかった。直接呼び出しでこれを忘れると、
日付が 0 のまま凍結し、日次処理が一切走らない。**例外は出ず、全 seed で
所持金が初期値付近に張り付くだけ**だった。修正は 1 行。

```py
for n in range(steps - 1):
    state[0].action = agent0(state[0].observation)
    state[1].action = agent1(state[1].observation)
    interpreter(state, env)
    state[0].observation.step = n + 1     # ← これが無いと時間が進まない
```

**教訓**: 速い経路を作るときは、遅い経路が暗黙に担っていた責務
（時間の進行、エピソード終了判定、観測の更新）を列挙してから剥がす。

## 4. 等価性テストこそが本体

高速版の価値は「速いこと」ではなく「**速くて、かつ公式と一致すること**」。

- 等価性テストは複数 seed × 複数エージェントで最終状態の完全一致を assert する。
- 依存ライブラリのバージョンを上げたときに必ず走らせる。
- **テストが本当にバグを捕まえるかを mutation で確かめた。** 時間を進める 1 行を消すと 17 件中 15 件が失敗し、検出できていた。ループ上限を 1 増やす変異は全件成功したが、調べると engine が終了後の呼び出しを無視するため無害な変更だった。テストの説明文から誤った主張を削った。

## 5. 状態の複製コスト（先読み用途）

| 操作 | コスト | スループット |
|---|---|---|
| `deepcopy(state)` | 151 µs | 約 6,600 回/秒 |
| 620 ステップの rollout | 14.4 ms | 約 70 本/秒 |

複製した状態で rollout しても元の状態は変わらないことを確認した。
モデルベース RL や MCTS で環境を複製する場合の目安になる。

## 6. 当時「やらない」と決めたこと

- ゲームロジックの自前実装: 1.7% のためにルール乖離のリスクを負わない。
- 高速版を既定にすること: 検証は本番と同じ経路で行う。
- 大規模 RL 用の環境を先行して作ること: 必要性を実測で示してから着手する。この判断の後、実際に必要になって作ったのが `jax-gpu.md` の JAX 版である。
